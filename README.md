# ThinkLessScheduleMore

Sends sweet "thinking of you" texts to a partner at random times throughout
the day, from your real phone number — no bot, no third-party service.

Full design notes (core loop, platform differences, future plans) live in
[`shared/ARCHITECTURE.md`](shared/ARCHITECTURE.md). This README covers
setup, structure, and current build status.

## Two platforms, one design

| | Android | iOS |
|---|---|---|
| Language | Kotlin | Swift (SwiftUI) |
| Storage | `SharedPreferences` | `UserDefaults` |
| Sending | `SmsManager`, silently, from a foreground `Service` | Local notification → user taps → Messages app opens pre-filled → user taps Send |
| Why the difference | Android allows apps to send SMS directly | Apple does not allow apps to send SMS silently |

Both apps implement the same core loop: pick a random time inside a
user-defined window, pick a random message from a user-created pool, send
(or prompt to send) it, log it, then pick the next random time.

## Android setup

Requirements: JDK 17+, Android SDK (compileSdk 36 / minSdk 26).

```bash
cd android
./gradlew compileDebugKotlin   # compile-only sanity check
./gradlew assembleDebug        # build a debug APK
```

Open the `android/` folder directly in Android Studio to run on a device
or emulator. `android/local.properties` (your local SDK path) is
git-ignored and must be created locally — Android Studio does this for
you on first open.

**Build types:** `debug` (applies a `.debug` applicationId suffix so it
can be installed alongside a release build) and `release` (R8
minification + resource shrinking enabled). Release builds are
intentionally unsigned in this repo — signing requires a real keystore,
which is not checked in. Generate one and configure a `signingConfig`
locally if you need a signed release build.

Runtime permissions requested on first launch: `SEND_SMS` (required to
send at all) and, on Android 13+, `POST_NOTIFICATIONS` (required for the
foreground-service notification). If either is denied, the app keeps
running but the corresponding feature silently no-ops — sends fail and
get logged as `failed` in the send history, or the persistent
notification just doesn't show.

## iOS setup

Requirements: Xcode 15+ (iOS 17 deployment target), [xcodegen](https://github.com/yonaskolb/XcodeGen).

```bash
cd ios
xcodegen generate              # regenerate .xcodeproj from project.yml
open ThinkLessScheduleMore.xcodeproj
```

Or build from the command line:

```bash
xcodebuild -project ThinkLessScheduleMore.xcodeproj \
  -scheme ThinkLessScheduleMore -sdk iphonesimulator \
  -destination 'generic/platform=iOS Simulator' build
```

Re-run `xcodegen generate` any time you add/remove Swift files —
`project.yml` is the source of truth, not the `.xcodeproj` itself
(which is still committed so the project opens without xcodegen
installed, but stays in sync with `project.yml`).

**Build configurations:** Debug and Release are already set up (xcodegen
default), with `SWIFT_ACTIVE_COMPILATION_CONDITIONS: DEBUG` scoping debug
code. No further environment separation exists or is needed — this is a
local-only app with no backend.

Notification permission is requested on first launch. If denied,
scheduled notifications simply won't be delivered — logged in the
console, not the send history (iOS doesn't tell the app when a
notification fails to appear).

## Testing

Neither platform currently has a test target/directory. Verification for
this pass was limited to compiling/building both apps successfully
(`./gradlew compileDebugKotlin` / `compileReleaseKotlin`, and
`xcodebuild build` for the iOS simulator target) — there is no automated
test suite to run yet.

## Known gaps / ideas

Not yet implemented on either platform: multiple recipients, scheduled
one-off messages (birthdays/anniversaries), "no send" days, weighted
message selection, widgets, delivery reports, and localization. See
`shared/ARCHITECTURE.md` for the core design this would build on top of.
